# Zielmodus: process redesign and direct comparison

## Objective
Connect opportunity discovery, process redesign, evidence, value scenarios and pilot comparison in the existing private workspace. Cover improvements 1–8 agreed with the user.

## Execution instructions
1. Preserve existing proposed tasks and economics. Add optional current tasks, named process alternatives and low/high value assumptions. Do not infer missing baselines or silently overwrite user data.
2. Replace expanded task forms with an ordered swimlane canvas and one task inspector. Offer current/proposed/compare views, explicit redesign actions, task-card selection, undo and visible draft/save state.
3. Visualise active effort, waiting, rework and handover quality independently. Unknown values remain unknown; totals disclose incomplete coverage. Sequence-based timing is a workshop estimate, not simulation of parallel paths.
4. Compare current/proposed/named alternatives directly. Compare up to three use cases with aligned metrics, evidence and pilot gaps; retain map lenses and show selected-case details in place.
5. Add editable low/base/high assumptions, a cash bridge and separate capacity/quality outcomes. Avoid invented uplift percentages, double counting or automatic readiness approval.
6. Validate every added field on the authenticated backend. Keep existing conflict detection and private source handling. Back up the workspace before backend changes.
7. Verify model calculations, unknown/zero handling, persistence, backward compatibility and invalid-input rejection. Inspect desktop and narrow layouts and exercise the main browser journey. Publish through the existing GitHub Pages workflow.

## Acceptance
- Existing records open without mandatory migration and save without losing source or task links.
- Users can edit a selected task, attach cards, clone alternatives and compare them without leaving the design screen.
- Low/base/high assumptions are independent, editable and persisted; missing assumptions never become zero.
- Pilot status distinguishes missing evidence/prerequisites from documented readiness, not approval.
- Code and built assets contain no private card wording or credentials.
